# Meeting Controls

Windows版Stream Deck向けのWeb会議操作プラグイン。初期版はTeamsに対応し、同じ4ボタンで将来の会議サービスを扱える構成です。

## 操作

- マイク：ミュート／解除。実際の状態を読み取って表示。
- カメラ：オン／オフ。
- 共有：未共有ならTeamsの共有先選択画面を開く。共有中なら停止。
- 退出：通常押下で自分が退出。「全員の会議を終了」は選ばない。

通話中の判定は会議の退出ボタンを基準とします。検出済みの会議で共有先選択画面が開いた間は通話中を維持し、操作を一時的に無効化します。複数の会議を検出した場合は自動選択せず、ボタンの設定画面で対象を指定します。対象指定は4ボタンで共通です。会議が終了したら対象を自動選択へ戻してください。

非通話中、操作不可、状態不明を区別します。取得情報が古い場合は操作しません。UI Automationが停止した場合は補助プロセスを再起動します。会議タイトルは操作対象の設定表示にのみ利用し、外部送信しません。

キー上に操作名や「通話なし」の文字は表示せず、アイコンと色で状態を示します。通話中は下部に会議アプリ名のみを表示します。共有先選択中は共有ボタンだけが黄色になり、ほかのボタンは直前の表示を保ちます。選択中の操作は引き続き一時的に無効です。

ミュート・カメラ操作でTeamsが前面に出た場合は、直前に作業していたウィンドウへ戻します。共有・退出には適用しません。実際のマウス・キーボード入力や第三のアプリへの切り替え、元ウィンドウの終了・最小化を検知したら復帰を中止します。入力の判別ではWindowsの低レベル入力通知の合成入力フラグのみを使い、キーの値・文字・座標は記録しません。短時間の緩和策なので、Teamsが一瞬前面に出ることやWindowsの制限で復帰できない場合はあります。

Stream Deckからマイク・カメラを操作し、Teamsで実際に状態が変化したことを確認すると、作業画面の中央に状態を約1.1秒表示します。「マイク ミュート」「マイク オン」「カメラ オン」「カメラ オフ」をアイコンとともに示します。表示はフォーカスを奪わず、クリックも透過します。初期状態の取得、状態不明、操作未反映、共有・退出では表示しません。

## 開発

Node.js 24以上、Stream Deck 7.1以上、Windows PowerShell 5.1を使用。Windows標準のUI Automationを使うため.NET SDKの追加インストールは不要です。このプロジェクトには開発用Node.js 24もローカル導入しています。

```powershell
npm ci
npm run typecheck
npm test
npm run build
npm run validate
npm run link
```

システムのNode.jsが古い場合は `node_modules/node/bin/node.exe` で各開発ツールを実行できます。Stream Deck内ではマニフェストで指定したNode.js 24が使用されます。

ビルド出力は `com.meetingcontrols.streamdeck.sdPlugin/`。Stream Deckにリンク後、右側の「Meeting Controls」から4つのアクションを空きキーへ配置してください。既存のキー配置は自動変更しません。

配布パッケージは `npm run pack` で作成します。現段階の識別名は公開前の仮名称です。

## 構成

- `src/plugin.ts`：Stream Deckの4アクションと設定。
- `src/core.mjs`：アプリ共通の通話選択と表示モデル。
- `src/bridge.mjs`：Teams補助プロセスとのJSON行通信、タイムアウトと再起動。
- `src/teams.ps1`：Teamsの検出、UI Automationによる状態取得・操作。
- `src/FocusReturnGuard.cs`：ミュート・カメラ操作に伴うフォーカス移動の緩和。
- `src/TransitionNotices.cs`：操作後の実状態を確認してから中央表示を要求。
- `src/MeetingOsd.cs`：非アクティブ・クリック透過の中央表示。
- `src/settings.html`：操作対象の選択。

ZoomやDiscordは、共通の状態モデルと `execute(kind, session)` を実装する別プロバイダーとして追加する想定です。現時点ではこれらの検出・操作は実装していません。

## 検証と制約

実装前に個人用Teams `26260.1717.5229.7049` でマイク・カメラ・共有の状態取得、最小化中の取得、ミュート切り替え、退出操作を確認しました。この結果と、ビルドしたプラグインの実機検証は別です。

初期実装の型チェック、7件の共通ロジックテスト、補助プロセスの通信と無効な対象の拒否、Elgato公式CLIでの検証・パッケージ生成に成功しました。Stream Deck本体への登録・接続と補助プロセス起動も確認済みです。実機キーの押下、会議中の継続的なアイコン同期は最終確認が必要です。

UI AutomationのボタンID・ラベルはTeamsの公開APIではありません。未認識の状態ラベルでは操作を無効化します。日本語と主要な英語ラベルに対応していますが、仕事用アカウント、組織の制限、画面共有中の退出メニュー、Teamsの更新後には追加検証が必要です。アクセシビリティ情報が取得できない環境でシステム設定を勝手に変更する処理はありません。

## 応答速度

操作要求は入力スレッドから待機イベントを解除して優先処理します。操作直後に状態を読み取り、Teams側の更新を追うため短い間隔で追加取得します。操作後の固定300ms待機はありません。通常の状態監視は750ms間隔を維持し、常時の高頻度探索は避けています。会議でないウィンドウは退出ボタンの有無だけで探索を打ち切ります。

`scripts/latency.mjs` は存在しない会議への要求を5回送り、拒否応答までの時間を測る読み取り専用の診断です。変更前は平均853ms、変更後の最終測定は平均71ms（99/39/68/96/53ms）でした。変更途中には一度約3秒の外れ値がありました。これは実際のキー押下からTeamsの操作完了・アイコン更新までを測った数値でも、API方式との比較でもありません。UI Automationの応答時間はTeamsの状態によって変わります。
